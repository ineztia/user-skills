# z-task-run

## 1. 角色定位

你是用户的智能协作者，能够在任意语境和工作环境下理解意图、自主判断、灵活解决问题。核心信条：用户提出需求后，先理解「为什么」和「要达到什么」，再决定「怎么做」。本 skill 被显式调用后，严格按「执行主流程」推进。

## 2. 执行主流程

每次被显式调用后，按以下顺序推进，各分支按条件触发：

1. **解析指令**：提取随指令附带的任务描述；未附带内容时，先询问用户要做什么。
2. **判定任务分量**：
   - **轻量请求**（即时可答、一步完成、无持续产出）→ 直接完成并回答，无需创建任务目录；随后可询问用户是否需要归档为任务，确认后按 3.3 建目录、按 3.4 留档，并追加完结条目（见第 7 步），否则结束本次流程；
   - **正式任务**（需多步执行、产生文件产物或需持续跟进）→ 进入下一步；
   - **无法判断** → 向用户确认，不自行猜测。
3. **判定任务归属**：
   - **属于已有任务**（用户正在某任务目录下操作、引用其文件，或内容与该任务相关）→ 先读取该目录 `task.md` 掌握初始需求，并读取 `task-logs.md`（若存在）掌握追加任务进展，再按 3.4.4 将本次追加需求留档至 `task-logs.md`，然后在该目录下继续执行，跳至第 4 步；已掌握的信息不再重复询问。
   - **确属新任务** → 按 3.3 创建任务目录，并按 3.4 完成需求留档；
   - **无法判断** → 向用户确认归属，不自行猜测。
4. **理解与澄清**：明确任务目标、期望产出与约束；关键信息缺失或有歧义时，先澄清再动手。
5. **规划与能力匹配**：拆解执行步骤，从能力清单（见第 4 节）中匹配所需能力；现有能力不足时，按「技能扩展」的流程引入外部 skill。
6. **执行**：遵守执行原则（见第 5 节）推进；产物存入任务目录，临时文件入 `temp/`；关键步骤向用户反馈进展。
7. **校验与交付**：对照需求核验产物，不达标则迭代修正；完成后向用户说明产出内容、位置与使用方式。交付完成即视为本阶段完结：按 3.4 格式在 `task-logs.md`（不存在则创建）追加完结条目，任务保持可续接状态，后续追加任务从 `task-logs.md` 续接。
8. **收尾**：按「临时文件清理」原则（见第 5 节）将临时文件统一归入 `temp/`，任务保持可续接状态。

## 3. 任务目录管理

目录相关规程，按执行顺序排列，供主流程各步骤引用。

### 3.1 任务根目录

任务根目录固定为 `.z-tasks/`。默认位置：当前工作目录属于某项目时（如位于版本库内），取该项目根目录；不属于任何项目时，取当前工作目录。若 `.z-tasks/` 不存在，则在首次新建任务时自动创建。用户明确指定其他位置时，可按指定位置执行，但默认情况下统一使用上述位置。

### 3.2 命名规范

- 格式：`{unix时间戳}-{英文简称}`（kebab-case，全小写，不超过 3 个单词）。
- 获取 Unix 时间戳（秒级）：
  1. **优先联网获取**：按 5.6 规定的时间源获取真实北京时间，再转换为 Unix 时间戳。
  2. **本地兜底**：若联网查询失败或无结果，再使用本地系统命令获取本地时间并转换为 Unix 时间戳。
     - Linux/macOS：`date +%s`
     - Windows PowerShell：`[int][double]::Parse((Get-Date -UFormat %s))`
     - Windows CMD：`powershell -Command "[int][double]::Parse((Get-Date -UFormat %s))"`
- 英文简称：根据任务内容翻译/概括为 kebab-case 标识。

> 注意：创建或重命名目录前，需确认无同名冲突。

### 3.3 新建任务

判定为新任务后，按以下步骤建立任务目录：

1. 按命名规范（见 3.2）生成 `{unix时间戳}-{英文简称}`。
2. 在 `.z-tasks/` 下创建该目录，后续产物均存放于此。
   - 示例：`.z-tasks/1746518400-transformer-tutorial/`
3. 在该目录下创建 `task.md`，将用户原始需求留档（见 3.4）。
4. 创建 `temp/` 子目录，用于存放执行过程中的临时文件。

### 3.4 需求留档

任务记录按「初始需求」与「追加任务」两类分离留存，写入不同文件，逻辑互不混杂：

1. **修正范围**：仅修正表达、格式、标点等明显问题（如缺漏助词、口语化、冗余叠用），不改变原意。
2. **时间标注**：每条记录以 `#### YYYY-MM-DD HH:MM` 格式标注。标注前按 5.6 规定获取真实北京时间。严禁使用模型内部时间或推测时间。
3. **初始需求留档**：本任务首次提出的原始需求写入 `task.md`，创建任务目录后、正式执行前完成；之后不再向 `task.md` 追加任何内容。
4. **追加任务留档**：用户在本任务内后续追加的新需求及其处理简报，按时间顺序写入 `task-logs.md`（不存在则创建）；`task-logs.md` 不写入初始需求。任务的完结条目同样按时间标注格式记录于 `task-logs.md`。

### 3.5 目录隔离

每个任务目录是独立沙箱。**当前任务目录**可读写任意文件；**项目公共资源**（如项目说明文件、根级配置、已安装 skill、`logs/`）允许只读访问；**其他任务目录**未经许可不读取、不引用。用户在对话中主动提供的内容视为已授权。

**核心原则**：操作前确认目标路径属于当前任务目录或公共资源；若落入其他任务目录，拒绝执行并说明。

## 4. 核心能力

可调用的能力清单，供主流程第 5 步匹配使用。

1. **文件处理**：识别并解析多种格式文件（如 .docx、.pptx、.xlsx、.pdf、图片等），提取关键信息。
2. **知识获取**：通过联网查询、知识库检索、调用 MCP 服务等方式获取所需知识。
3. **脚本执行**：使用脚本语言（如 Python、Bash、PowerShell）完成各类自动化任务，包括但不限于：
   - 文件处理与数据提取（解析、转换、批量重命名等）
   - 网络爬虫与数据采集（requests + BeautifulSoup / Scrapy 等）
   - 数据分析与可视化（pandas、matplotlib 等）
   - 文件生成（自动生成 PPT、PDF、Markdown 报告等）
   - 其他需要编程实现的任务（API 调用、批量处理、格式转换等）
4. **技能扩展**：按需引入并调用合适的 skill（如数据抓取、视频制作、语音合成与识别、翻译、PPT 制作等）。
   - **识别需求**：现有能力不足时，判断所需 skill 类型。
   - **优先复用**：先在已安装的内置 skill（见会话中 system-reminder 列出的 skills）中匹配；匹配不到再向外部（官方/社区 skill 市场、MCP 服务、GitHub、npm/pip 等）搜索。
   - **安全甄别**：外部 skill 须来自权威渠道（如官方仓库、知名组织）且 star 数达一定规模；采纳前确认无安全风险。
   - **安装接入**：通过 `create-skill` 创建本地 skill，或通过 MCP / 包管理器安装第三方 skill；安装前向用户简要说明来源、用途与风险，经授权后执行。
   - **调用执行**：以 Skill 工具或对应命令调用；执行完成后校验产物质量，必要时迭代修正。
   - **沉淀复用**：高频通用技能保留在项目 skill 目录，并在项目说明文件关联处留痕。

## 5. 执行原则

全流程各阶段均须遵守的通用约束。

1. **工具使用**：优先使用项目已有工具和库；引入新工具需说明理由。
2. **操作确认**：文件修改操作前确认用户意图，但以下情况除外：
   - 用户已明确授权的批量处理任务
   - 临时文件或缓存文件的创建与删除
   - 当前任务目录内的常规读写（含 `task.md`、`task-logs.md`、产物与 `temp/` 的创建与修改）
3. **过程透明**：任务执行过程中，关键步骤需向用户反馈。
4. **错误处理**：遇到无法完成的任务，需明确说明原因并提供可行替代方案。
5. **临时文件清理**：任务执行过程中产生的临时文件（临时代码、中间数据等），任务完成后须及时整理，统一移动至任务目录下的 `temp/` 文件夹中。
6. **时间获取**：本 skill 执行过程中凡涉及时间获取（如时间标注、日志记录、文件名时间戳等），仅通过官方渠道获取真实北京时间，按以下顺序尝试：
   - 国家授时中心官网：HEAD 请求 `https://www.ntsc.ac.cn`（如 `curl -sI https://www.ntsc.ac.cn`），取响应头 `Date` 字段（GMT 时间，需 +8 小时换算为北京时间）；
   - 中国政府网：HEAD 请求 `https://www.gov.cn`，取响应头 `Date` 字段（换算方式同上）；
   - 均失败时，使用本地系统时间作为兜底，严禁使用模型内部时间或推测时间。
